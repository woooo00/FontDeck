- [ ] **字体是否真的应用成功**：已加 `appliedFont` 回报与中文名回退，但 `app.textFonts.getByName("STXinwei")` 在 AI 29.6 里是否命中，尚未在真实文档里确认。状态栏会显示实际字体名。
- [ ] **旋转 / 倾斜的转曲文字（2026-11-10 起冻结研发）**：已有实验性自动摆正（PCA 估角 + 严格守卫），合成旋转稿 5 个角度 3/3，4 份历史水平稿全部判定「不摆正」、零影响（见 `scripts/verify-release.py`）。但**真实 AI 旋转稿、`unrotateBox` 回写文档坐标、竖排 / 倾斜行均未实机验证**。按用户决定不再继续投入、不承诺效果；遇到这类稿子先跳过或手动摆正后再识别。
- [ ] **描边转曲、多图层叠加、剪切蒙版**：`fdGeomWalk` 只遍历 pathItems / compoundPathItems / groupItems，蒙版内或外观复杂的对象可能漏形状 → 表现为「少字」。
- [x] **西文整行识别**（2026-11-10 11:40）：实测 `3. Fold the cord ... packaging.` 整句含空格标点 100% 正确（0.925）。做法是新增整行 OCR 通道 + 整行恢复，逐字框降级为折叠的校对区。原来的「按字宽切框」对字母不成立，已不再用于取文本。

- [ ] **行分界算法的极端情况**：核心墨迹带阈值（峰值 15%）、近邻合并阈值（中位带高 0.5）、零间隙硬切（>=4px 且两侧都够高）在 **52 张**历史渲染图上核过，只有超粗综艺体那张发生了变化。竖排文字、图文混排选区、倾斜行、行间完全没有空白（上下行笔画相接）尚未验证 —— 这类问题现在可以一键生成诊断日志，直接看 `bands` 对不对。

- [ ] **非中文/拉丁/西里尔的语种**：目前自动切换只覆盖东斯拉夫语（俄语 / 乌克兰语 / 白俄 / 保加利亚）。日语、韩语、希腊语、阿拉伯语、泰语仍会用中英模型凑字形，需要另配对应 rec 模型。`packages/ocr/models/` 目前只有 `eslav_rec.onnx`。
- [ ] **整篇统一字号**：现在每行各自做宽度闭环，字体完全正确时各行字号也有约 ±6% 差异（俄语稿反推 6.1~6.5pt）。原稿通常是统一字号，若要严格还原，应取各行字号中位数统一应用、残差交给 tracking。本轮未做，重测后若仍觉得字号不齐再改（会动 JSX，需重启 AI）。
- [ ] **自动语种切换阈值**：`< 0.86` 触发重跑、`高出 0.05` 且西里尔占比 `> 0.12` 才接管，只在俄语长稿 + 中/英文共 3 类稿子上验过。混合语种（中英俄混排）可能整篇偏向其中一种。
- [ ] **逐字定位的西文**：整行恢复不给每个字母单独位置（做整句编辑本来也不需要）。若将来要逐字改色、错位排版，还得按字母 advance 宽切框。
- [ ] **字体字重的区分度**：整行轮廓比对能准确命中字体族（英文 MiSans 包揽前五、中文华文新魏 0.99 对第二名 0.90），但同族不同字重分数很接近（MiSans Normal 0.9569 vs Regular 0.9547）。用户可在下拉里换。
- [ ] **字体推荐的绝对精度**：算法是 16×16 密度向量余弦，本质是「轮廓相似」而非字体识别。合成数据里黑体/宋体精确命中第一名，雅黑被推成「等线 Bold」（很接近但不对）；超细字重的真实稿会倾向推荐本机其他 Thin 字体。**下拉可换，不要当鉴定结果。**
- [ ] **分类准确度**：等线被判手写体、Raleway 未分类，索引阶段的分类规则仍需调。

### 2026-11-17 恢复字体应用 / 自动分段（FD-20261117-142243 驱动）

- [ ] **JSX 字体解析与回读校验**：`fdResolveFont` 会在 `getByName` 返回的家族对不上时拒掉，再查惰性字体索引（PostScript 名 / 家族名 / 「家族+字重」），最后仍找不到就报「字体不可用」。**没在真实 AI 里跑过** —— 用户下次恢复时看面板有没有「字体没应用上，实际用了 X」即可验证。若 AI 里 Gabriola 真不存在，这条会如实报错而不是静默换成 Candara。
- [ ] **自动分段的结果要不要用在恢复上**：整行分数 < 0.6 时服务端会拆两段各自比对并在面板里直接采用（实测 0.492 → 0.8199 / 0.9434）。段框、字号换算、多文本框落位**只在数据层验证过**，没在真实 AI 里点过「恢复」。
- [ ] **段框裁掉行首装饰符后的位置**：`split_line_gaps` 现在会把段首圆点从框里裁掉（`l: 32 → 80`）。理论上一段文字的落点右移更准，实机位置差多少还没量过。
- [ ] **家族共识 / 字重优先的边界**：短段（≤12 字）会向长段的字体家族靠拢，再在同族里挑 `weightFit` 最高的字重。如果长段本身选错了家族，短段会跟着错（一致性优先于独立判断）。中英混排、两端字族确实不同的稿子可能被强行统一。
